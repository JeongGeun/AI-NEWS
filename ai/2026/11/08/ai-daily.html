1. MCP 서버 개발: 도구 설명이 핵심 API

출처: Dev.to · 중요도: 보통

한국어 요약: Model Context Protocol(MCP) 서버 개발 시 대부분의 개발자들이 기존 REST API를 단순히 래핑하고 엔드포인트마다 도구를 노출하는 실수를 한다. 실제 중요한 것은 LLM이 런타임에 JSON 스키마를 읽고 올바른 도구를 선택할 수 있도록 도구를 설계하고 설명하는 것이다. TypeScript SDK v2와 Zod v4, Valibot 등의 Standard Schema를 활용하여 효과적인 MCP 서버를 구축하는 방법을 제시한다.

English Summary: This article addresses common pitfalls in MCP server development, where developers often wrap existing REST APIs without proper tool design for LLM consumption. The key insight is that tool descriptions for JSON Schema at runtime, not code documentation, should be the focus. It demonstrates building a minimal MCP server using TypeScript SDK v2 with Standard Schema support.

핵심 키워드: Model Context Protocol, TypeScript SDK v2, Zod, Standard Schema, Deploy pipeline

2. AI는 이해했지만 Rust 코드가 거부했다: SpendGuard의 결제 보안

출처: Dev.to · 중요도: 보통

한국어 요약: Solana 해커톤에서 개발된 SpendGuard는 자연어 AI 명령을 결제 제안으로 변환하되, 결정적인 Rust 코드가 정책 검증을 수행하는 결제 에이전트다. AI의 이해와 실제 권한 부여 사이의 간극을 활용해 지출 한도, 수신자 화이트리스트 등의 정책으로 불정당한 거래를 차단한다.

English Summary: SpendGuard is a Solana payment agent that separates AI understanding from authorization: an LLM parses natural language payment requests, but deterministic Rust code enforces policies before any transaction is signed. This gap between comprehension and authorization prevents unauthorized payments even when AI understands malicious instructions.

핵심 키워드: SpendGuard, Solana, MLH Solana Hackathon, Rust, LLM

3. osFoundry MCP 도구 목록이 Codex 토큰에 미치는 영향과 최적화 방법

출처: Dev.to · 중요도: 보통

한국어 요약: osFoundry의 MCP 서버에서 59개 도구 목록을 조회하는 과정에서 발생하는 토큰 소비를 분석한 기술 문서입니다. Codex CLI가 MCP 핸드셰이크 후 tools/list 호출 시 45KB 이상의 응답을 받으며, 이후 모든 모델 요청에 이 도구 선언이 포함되는 구조를 설명합니다. 프로젝트별로 필요한 도구만 선택하여 토큰 사용을 최적화하는 방법을 제시합니다.

English Summary: This technical article analyzes how osFoundry’s MCP tool list impacts token consumption in Codex. The MCP client receives 59 tools (~45KB response) during initialization, which are then included in subsequent model requests. The article examines token overhead and provides guidance on selectively loading tools per project to optimize token usage.

핵심 키워드: osFoundry, Codex CLI, MCP (Model Context Protocol), tools/list API

4. osFoundry가 Claude에게 GitNest 직접 푸시 대신 변경 제안만 허용하는 이유

출처: Dev.to · 중요도: 보통

한국어 요약: Claude를 통한 파일 업로드 시 osFoundry는 ‘propose_gitnest_file_import’ 도구를 사용해 변경안만 준비하고 실제 커밋은 저장소 소유자의 승인이 필요하다. 필수 idempotency_key 검증으로 중복 요청을 방지하며, Git 저장소에 직접 접근하는 도구는 존재하지 않는다. 이는 AI 에이전트의 쓰기 권한을 안전하게 제한하는 아키텍처 설계 사례를 보여준다.

English Summary: osFoundry restricts Claude’s file uploads to the GitNest repository through a ‘propose_gitnest_file_import’ tool that only prepares changes, requiring repository owner approval for actual commits. The tool enforces mandatory idempotency keys with minimum length validation to prevent duplicate requests, and no tools directly access the Git repository. This demonstrates a secure architectural pattern for controlling AI agent write permissions.

핵심 키워드: osFoundry, Claude, GitNest, MCP endpoint, idempotency_key

5. 장시간 자율 코딩 강화한 Inkling 2 Small MoE 모델 공개

출처: GeekNews (개발자) · 중요도: 높음

한국어 요약: Inkling이 594B 파라미터(17B 활성화)의 혼합 전문가(MoE) 모델인 Inkling 2 Small을 발표했습니다. 이 모델은 이전 세대 대비 성능이 크게 향상되었으며, 특히 장시간 자율 코딩, 비전 능력, 지식 작업에서 우수합니다. 초기에는 Tinker를 통해 제한된 가중치로 제공되며, 다음 주 안전 테스트 완료 후 Apache 2.0 라이선스로 전체 가중치를 공개할 예정입니다.

English Summary: Inkling introduces Inkling 2 Small, a Mixture-of-Experts model with 594B total parameters (17B active) that significantly outperforms previous generations in agentic coding, vision, and reasoning tasks. The model will initially be available through Tinker with closed weights, with full open weights under Apache 2.0 license released after external safety testing.

핵심 키워드: Inkling, Inkling 2 Small, Tinker, Apache 2.0
